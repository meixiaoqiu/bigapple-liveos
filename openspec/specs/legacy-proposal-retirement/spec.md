# legacy-proposal-retirement 规格

## Purpose

确保旧提案体系被完整、可证明地移除，使所有尚未迁移到统一提案系统的业务明确失败关闭，并通过机械检查阻止任何旧实现、旧字段或隐式兼容路径继续运行。

## Requirements

### Requirement: 旧提案系统必须完整移除
系统 MUST 不再包含或运行旧提案、旧投票、旧执行及其专用选民规则实现。删除范围 SHALL 覆盖权威模型、数据库结构、领域服务、Admin、命令、信号、事件、API、URL、模板、仿真、演示数据和测试辅助代码，不得保留兼容门面或回退路径。

#### Scenario: 扫描产品代码和数据库结构
- **WHEN** 项目执行旧提案残余检查
- **THEN** 检查找不到旧模型、旧表、旧字段、旧服务、旧路由或运行时导入

#### Scenario: 业务尝试回退到旧系统
- **WHEN** 新增或修改的业务代码引用任何已登记的旧提案标识
- **THEN** 项目检查和 CI 失败，不允许该引用进入可运行版本

### Requirement: 未迁移业务必须失败关闭
尚未由统一提案系统承接的用户流程 MUST 明确显示暂不可用，不得创建旧提案数据、直接改变原本需要提案决定的权威状态、返回伪成功或因残余引用产生服务器错误。成员准入只有在新统一提案生命周期、选民规则、授权执行和审计验收全部通过后才能退出失败关闭；其他未迁移业务继续保持关闭。

#### Scenario: 成员准入完成迁移
- **WHEN** 新统一提案系统已完整承接成员准入并通过自动化与 real/simulation 验收
- **THEN** 系统开放成员准入的创建、投票、判定和授权执行入口，且不恢复任何旧提案实现

#### Scenario: 其他业务尚未迁移
- **WHEN** 角色任命、角色卸任、财务职责任命、社区共议、守约事务、专业事务、管理事务、反馈转行动或仿真决策尚未由新系统完整承接
- **THEN** 对应入口继续明确失败关闭，不得借用成员准入适配器或直接修改权威状态

#### Scenario: 后台或仿真触发未迁移流程
- **WHEN** Admin、管理命令、仿真或演示数据尝试触发尚未迁移的提案业务
- **THEN** 系统以可识别的领域错误或检查失败终止，不得绕过提案直接写入最终状态

### Requirement: 业务制度语义必须保留为迁移清单
删除旧技术实现时，系统 SHALL 保留每种旧提案业务的发起资格、参与者规则、决策阈值、截止规则、执行动作和审计要求，并将其记录为统一提案系统的待迁移验收项。不得把删除实现解释为取消制度要求。

#### Scenario: 旧业务依赖被发现
- **WHEN** 依赖审计发现成员准入、角色任命、财务职责或其他业务使用旧提案
- **THEN** 迁移清单记录业务入口、制度规则、当前依赖和恢复该功能所需的新系统能力

#### Scenario: 删除仅证明旧实现的测试
- **WHEN** 某项测试直接依赖旧模型或旧服务
- **THEN** 删除旧实现断言，同时保留或新增失败关闭测试及对应业务制度验收项

### Requirement: 未上线数据库不得保留旧提案残余
项目 MUST 以未上线环境为前提删除旧提案表、字段、索引、约束和迁移定义，不提供旧数据转换、双写或兼容读取。开发者 SHALL 通过明确重置 world 数据库应用干净结构。

#### Scenario: 创建全新数据库
- **WHEN** 从空数据库应用当前迁移
- **THEN** 数据库中不存在旧提案相关表、字段、索引或约束

#### Scenario: 现有开发数据库仍有旧结构
- **WHEN** 启动或迁移检测到需要重置的旧提案结构
- **THEN** 系统停止并给出明确重置说明，不静默保留或转换旧数据

### Requirement: 公开契约和文档必须与删除结果一致
所有公开 API、schema、payload、数据库结构、产品说明和开发指南 MUST 不再把旧提案体系描述为可用实现，并 MUST 明确列出暂时关闭的流程和后续统一提案系统迁移边界。

#### Scenario: 执行文档和契约一致性检查
- **WHEN** 删除工作完成后运行文档、contract 和代码引用扫描
- **THEN** 不存在指向旧端点、旧字段或旧模型的有效说明，过程历史仅保留在 OpenSpec 变更与 Git 历史中
