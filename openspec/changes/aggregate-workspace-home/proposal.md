## Why

当前 Workspace 首页按任务、提案、采购、申诉等业务模块分别展示信息，成员难以首先判断哪些事项与自己有关、当前轮到谁行动以及下一步能做什么。本次变更在不替代领域模型的前提下增加统一工作事项投影，并以可回退的方式调整首页信息层级。

## What Changes

- 在 Workspace 首页增加“我的事务”聚合区域，统一回答事项类型、当前状态、责任归属、当前处理方、成员可执行动作和更新时间。
- 将需要当前成员处理、等待他人处理和最近结束的事项分组展示。
- 复用任务、申诉、提案和采购等现有领域模型、服务及权限判断，不新增通用事务表、统一状态机或新的授权路径。
- 将尚未领取的开放任务作为“可参与事项”而非个人事务处理。
- 本次只增加投影并调整首页顺序；现有 Workspace 首页模块、表单、按钮、链接、权限条件和操作能力全部保留，仅整体下移到新聚合区域之后。
- 形成旧模块待确认清单，后续删除或迁移必须由使用者逐项确认，不属于本次变更。

### 目标

- 让成员进入首页后优先看到与自己相关的正式事项及行动责任。
- 通过只读投影统一展示，不把各领域差异压入新的通用业务内核。
- 保留旧首页作为迁移期对照，确保本次调整可验证、可回退。

### 非目标

- 不新增或修改权威业务模型字段。
- 不统一任务、申诉、提案和采购的状态机。
- 不实现责任转移、事务合并或拆分、重开、纠错事务、证据版本等远期机制。
- 不删除、合并或关闭任何现有 Workspace 首页模块和操作入口。
- 不改变 Observer、Admin、Simulation 或公开事件流的职责。

### 权限影响

聚合投影必须复用 `AuthorizationService` 及各领域已有权限判断。变更不新增 permission、角色、授权例外或模板侧权限推导；权限服务不可用时继续沿用现有失败关闭行为。

### 数据影响

无数据库 schema、迁移或权威状态写入变化。统一事务仅为请求期间生成的只读页面 context。

### 公开契约影响

无 API、schema 或 payload 变化。变更影响已登录成员可见的 Workspace 首页 HTML 和信息顺序。

## Capabilities

### New Capabilities

- `workspace-matter-projection`: 定义 Workspace 首页如何将现有领域对象投影为成员相关事务，并在保留全部旧模块的迁移阶段优先展示。

### Modified Capabilities

无。

## Impact

- 主要影响 `workspace/work_item_context.py`、`workspace/context.py`、`templates/workspace/index.html` 及 Workspace 测试。
- 首页模板使用 Tailwind class，实施阶段需要运行既有 Tailwind 构建并提交生成样式。
- Workspace 产品说明需要在 sibling `bigapple-docs` 仓库同步更新。
- 不新增依赖，不修改 API 或数据库。
