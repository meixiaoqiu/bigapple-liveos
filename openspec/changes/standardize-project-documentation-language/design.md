## 背景

变更动机见 `proposal.md`，规范行为见 `specs/project-documentation-language/spec.md`。

OpenSpec 当前通过 `openspec/config.yaml` 向各产物注入项目上下文和产物规则，但初始化模板没有语言约束。Live OS 与 sibling 文档仓库以中文使用者为主，代码标识和大量技术契约则必须保留稳定原文，因此不能使用简单的“禁止所有拉丁字母”规则。

## 目标 / 非目标

**目标：**

- 让新 OpenSpec 产物在生成阶段默认使用中文。
- 将语言约束保存为主规格，使其可以被长期读取、审核和演进。
- 提供确定性检查，识别普通英文说明，同时避免误报代码与专业术语。
- 让 Live OS 与 sibling 文档仓库遵守同一规则。

**非目标：**

- 不翻译代码标识、公开契约字段、命令、路径、URL 或第三方产品名。
- 不修改运行时业务行为。
- 不依赖外部 AI 或网络服务判断文档是否合规。
- 不要求把每一个拉丁字母都加入例外清单。

## 决策

### 1. 使用配置、主规格和检查三层约束

`openspec/config.yaml` 负责在生成阶段向 AI 注入中文规则；`openspec/specs/project-documentation-language/spec.md` 保存长期规范；确定性检查负责在提交或项目检查阶段发现遗漏。

只使用配置无法形成可测试的长期行为契约，只使用主规格又不能保证每次生成时自动注入，因此三层必须同时存在。

### 2. 按文档语义区块检查，不按字符检查

检查器先区分 Markdown 标题、普通段落、列表说明、表格说明、代码块、行内代码、链接和路径，再只对说明性区块检查明显的普通英文内容。

允许原文的内容包括：

- 围栏代码块和行内代码；
- 命令、文件路径、URL；
- API、schema、payload 与技术契约字段；
- 变量名、类名、函数名和协议名；
- 产品名、OpenSpec 结构关键字；
- 经过审核的专业术语。

备选方案：只要一行包含拉丁字母就失败。没有采用，因为会把正常代码引用和专业术语全部误报，迫使维护者翻译稳定语义标识。

### 3. 使用仓库内明确例外，不使用隐式 AI 判断

检查器的固定结构关键字和专业术语例外保存在仓库中，可由代码审查修改。任何文件级或行级忽略都必须写明理由，不允许以大范围目录忽略代替修复。

备选方案：调用 AI 判断一段英文是否属于专业术语。没有采用，因为结果不可复现，也会引入网络、成本和隐私依赖。

### 4. 先保证新增与修改内容，再清理历史存量

项目检查必须立即约束新的 OpenSpec 产物和后续修改的文档。对已有文档先生成完整盘点，再按文档所有权和风险分批清理；完成基线清理后，完整仓库检查不得再依赖历史豁免。

OpenSpec 目录是第一批必须完全合规的范围，因为它直接影响后续 AI 生成行为。

备选方案：在首次启用时阻塞全部仓库，直到所有历史文档一次性翻译完成。没有采用，因为可能把本次小型规范变更扩大为无法审核的大批量文档改写。

### 5. OpenSpec 结构关键字保持稳定

`Why`、`What Changes`、`Capabilities`、`Purpose`、`Requirement`、`Scenario`、`MUST`、`SHALL`、`WHEN`、`THEN` 等由 OpenSpec schema 或规范语义要求的关键字保留原文。关键字后的名称和相关行为说明必须使用中文。

这类关键字属于机器解析与规范语义，不视为普通英文标题。

## 风险 / 权衡

- [启发式检查可能误报技术文本] → 先解析 Markdown 语义区块，并使用小而明确的仓库内专业术语例外。
- [例外列表可能不断扩大并掩盖普通英文] → 例外按术语而非整段文本维护，文件级忽略必须写明理由。
- [两个仓库的检查规则可能漂移] → 在权威开发文档中定义共同规则，并由 Live OS 项目检查调用同一约定或共享数据文件。
- [历史英文文档数量较多] → 先生成盘点与基线，分批清理；新增和修改内容立即执行严格规则。
- [翻译技术字段会破坏契约] → 检查和人工审核均明确保护代码、schema、payload 与路径原文。

## 迁移方案

1. 更新 `openspec/config.yaml`，向全部 OpenSpec 产物与操作注入中文规则。
2. 同步 `project-documentation-language` delta spec 到主规格。
3. 修订当前 active OpenSpec 变更中的普通英文说明。
4. 增加只读语言检查与明确例外数据。
5. 盘点 Live OS 与 sibling 文档仓库的历史英文说明。
6. 分批清理历史存量，并在基线清零后对完整文档范围启用严格检查。
7. 将检查纳入项目检查和相关持续集成流程。
