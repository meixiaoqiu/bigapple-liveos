## Context

参见 `proposal.md`。当前 480px Workspace 首页把成员身份、world、模拟日和全部导航放在一个黄色 `header.card` 中；成员状态、当前积分、可用积分和历史贡献则在页面后部的四项 stats 中。设计稿只作为视觉参考，其示例积分、通知和功能按钮不是产品需求。

## Goals / Non-Goals

**Goals:**

- 只用现有模板上下文重组首页顶部，不增加 view 查询或展示层伪数据。
- 建立欢迎文案、双列摘要、身份元数据、下移导航四个稳定层级。
- 保证所有现有指标与入口在移动前后可追踪，便于回归测试。

**Non-Goals:**

- 不在本次引入头像、通知状态、Material Symbols、外部字体或 JavaScript。
- 不决定哪些现有入口最终属于快捷操作或底部导航。
- 不修改公共 `runtime_header.html`，不影响非 Workspace 页面。

## Decisions

### 1. 欢迎文案使用稳定的“你好，”

欢迎区域使用“你好，”和“欢迎回到工作台”，不根据服务端或客户端时间切换“早上好/下午好”。这样不需要新增时间、时区或缓存差异逻辑，本次仍是纯模板改造。

备选方案是直接照搬设计稿的“早上好”。它在其他时段会产生错误语义，并把视觉步骤扩大为动态问候功能，因此不采用。

### 2. 双列摘要只展示成员状态和当前积分

状态摘要采用一张有细边框、无重阴影的双列卡片。左列展示 `member.get_status_display`，右列展示 `credit_balance`。身份或资格作为状态的辅助文本，但不能取代成员状态；积分不增加设计稿示例中的固定值和“本周变化”。

备选方案是一次展示四项 stats。它会偏离设计稿顶部的信息密度，并让本次顶部改造过重，因此可用积分与历史贡献继续留在后续区域。

### 3. 身份和运行上下文使用紧凑元数据行

成员编号、`identity_display.membership` 或 `derived_status`、职责、world 与模拟日继续保留，但从黄色 badge 体系改为欢迎区下方的紧凑文本或弱化标签。模板必须保留身份分支与职责循环，不能把展示值写死。

备选方案是全部隐藏这些信息以追求设计稿简洁。它会删除当前页面承担的身份和运行上下文，因此不采用。

### 4. 导航从旧英雄卡中完整移出

导航 DOM 整体放在欢迎、摘要和元数据之后，继续使用既有分组、链接和 Django 条件。此步骤只改变位置和与黄色背景耦合的边框颜色，不把链接转换为设计稿的图标宫格。

备选方案是本次同时实现快捷操作卡片。由于设计者不了解实际功能优先级，提前选择六个入口会形成未经确认的产品决策，因此不采用。

该约束描述本 change 的交付边界和实施顺序，不禁止后续独立 change 在保留真实入口和权限条件的前提下把导航增量改为快捷操作卡片。当前后续增量由 `redesign-workspace-quick-actions` 单独定义和验证。

### 5. 指标通过迁移避免重复

页面后部的核心状态区域移除已经上移的“成员状态”和“当前积分”两个 stat，仅保留“可用积分”和“历史贡献”。这是信息位置迁移，不是删除指标。现有积分流水模块保持原位。

备选方案是在顶部复制两项并保留后部四项。它便于最小编辑，但会造成明显重复和错误的信息层级，因此不采用。

## Risks / Trade-offs

- [导航离开主色背景后原边框颜色对比不足] → 导航容器改用基础文本与 outline 语义色，但不改变按钮功能和分组。
- [顶部元数据仍比设计稿密集] → 本步骤优先保留事实；后续可逐项讨论哪些信息迁入资料页，未经确认不隐藏。
- [下部两项 stats 视觉上暂时不完整] → 接受迁移期状态，后续单独重设计余额和贡献模块，不在本步骤扩大范围。
- [测试只验证模板结构而非像素] → 对关键 class、指标出现次数、导航顺序和权限可见性做回归；视觉结果再人工预览。

## Migration Plan

先重组模板并增加回归测试，再重建 Tailwind CSS。无数据迁移。若回滚，恢复黄色英雄卡、导航位置和四项 stats 即可，服务端上下文无需变化。
