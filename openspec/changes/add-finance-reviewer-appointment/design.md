## Context

系统已经具有财务角色、`finance.review` 授权、通用角色任命提案、执衡者选民规则以及报销审核服务，但成员工作台没有把这些能力连接起来。设计必须复用现有权威模型，并保持固定 world 数据库路由和 OpenFGA 失败关闭边界。

## Goals / Non-Goals

**Goals:**

- 让典守者可从成员工作台提名守约者为财务审核者。
- 通过既有提案投票和执行产生可审计任命。
- 让新任审核者完成他人报销审核，并验证仿真 world 隔离。

**Non-Goals:**

- 不新增直接角色授予或特殊初始化旁路。
- 不在本变更开放付款者、公开发布者任命页面。
- 不改变报销附件、付款和公开副本流程。

## Decisions

### 复用通用角色任命提案

工作台调用既有角色任命提案服务，并将目标角色固定为基线财务审核者角色。这样任命自动保留提案、投票、执行和 `RoleAssignment.source_proposal` 证据。未采用“典守者点击后直接创建任命”，因为这会绕过现有治理生命周期。

### 页面操作按能力分离

提名和执行通过 `governance.manage_roles` 校验；投票完全交给既有选民快照和投票时资格复核。页面不能把典守者身份等同于执衡者身份，也不能由表单传入 actor 或任意角色 ID。

### 目标成员仅选择当前守约者

候选列表和服务提交都重新验证目标成员当前有效守约者资格、账号和成员状态。角色固定由服务端解析，避免客户端选择付款者或公开发布者。

同一目标成员的财务审核提名在一个数据库事务内锁定成员行并复查开放提案，使并发请求串行化。投票服务同样在统一事务内锁定提案，把投票、统一事件和提案状态计算作为一个原子操作；任一后续步骤失败时全部回滚。

页面中的候选人与当前审核者复用当前权限查询，统一检查任命状态、起止时间、角色状态、成员状态、登录账号和守约者前置资格，不把未来或自然到期任命当作当前职责。

### 不新增数据表

当前 `Proposal`、`ProposalVote`、`ProposalExecution`、`RoleAssignment` 与统一事件账本已经表达完整审计事实。增加平行申请表会造成状态重复，因此不采用。

## Risks / Trade-offs

- [唯一执衡者可以独自通过提案] → 这是当前选民规则在零起点 world 的既定结果；提案仍保留完整责任人和任期证据。
- [OpenFGA tuple 与任命生命周期不同步] → 增量投影只写当前有效任命，撤销在数据库提交后删除对应 tuple；自然到期、未来生效或成员资格失效由 `AuthorizationService` 在 OpenFGA check 前以 Django 权威事实否决，并惰性清理陈旧 tuple。OpenFGA 不可用或清理失败仍然失败关闭。
- [候选人和提案较多时页面变长] → 当前仿真规模有限，先提供分页前的最小治理入口，后续可增加筛选而不改变规格。

## Migration Plan

不需要 schema 迁移。部署工作台代码后，确认两个 world 已初始化财务基线角色；运行 OpenFGA tuple 重建。回滚页面不会删除已产生的合法提案或任命，历史事实继续有效。
