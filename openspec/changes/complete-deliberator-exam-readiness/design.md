## Context

现有考试页面始终显示开始按钮，`start_deliberator_exam` 到 POST 时才发现政策或题目缺失。默认考试数据来自迁移 `0045`，但 `flush` 会删除数据并保留迁移记录，因此 simulation 重置后可能无法考试。现有考试领域服务已经支持题目发布和政策发布，但业务管理员默认 `is_staff=False`，不能把 Django Admin 当作唯一配置入口。

## Goals / Non-Goals

**Goals:**

- simulation 重置后恢复一题仿真考试基线。
- 申请页面在提交前显示考试是否开放。
- 有权管理员能在 workspace 完成最小题目和政策发布。
- 所有写操作继续使用既有领域服务和具体权限。

**Non-Goals:**

- 不新增独立就绪检查命令或 JSON 输出。
- 不修改 `start.bat` 或建设启动诊断体系。
- 不建设考试统计、尝试审计、批量管理或完整题库后台。
- 不自动为 real world 发布示例考试。
- 不改变评分、任期和守约者前置资格。

## Decisions

### 1. 只抽取最小可用性判断

领域层提供一个无副作用的判断，返回 `ready`、`no_active_policy` 或 `insufficient_questions` 及必要数量。申请页 GET 和考试开始服务共同使用它；模板只需要知道能否开始，不建立复杂展示模型。

未采用独立诊断命令和多消费者状态框架，因为本次只需要消除页面与 POST 的行为差异。

### 2. 只在 simulation 生命周期恢复基线

抽取幂等仿真基线函数，在 zero-start reset 或仿真初始化后确保一题已发布基线和一项有效政策。已有可用配置时不写入，不覆盖题目、政策或考试历史。real world 始终要求管理员显式配置。

未采用数据迁移，因为 `flush` 后迁移不会重放；也不在 GET 中自动创建，因为读请求不应发布权威政策。

### 3. 普通成员只看到统一提示

考试不可用时，所有守约者统一看到“执衡者资格考试暂未开放，请稍后再试”，开始按钮禁用。页面不根据管理员身份追加诊断内容，避免分支文案和展示复杂度。

POST 仍重新检查，处理页面加载后配置变化的情况。

### 4. Workspace 只提供最小配置入口

对具有 `governance.manage_deliberator_exam` 权限的成员提供一个 world-scoped 页面，只完成：

- 创建并发布一道单选题；
- 输入抽题数量和及格百分比并发布政策；
- 显示当前已发布题目数量和当前政策。

写操作复用现有题目和政策服务，view 不直接改变 active 状态。高级版本复制、批量停用、统计和尝试审计不纳入本次。Django Admin 可以保留，但不再是完成首次配置的必要条件。

未采用给业务管理员设置 `is_staff=True`，因为技术后台身份不能替代 world 业务权限。

## Risks / Trade-offs

- [普通成员不知道具体缺项] → 这是有意简化；其无法处理配置问题，统一提示足够。
- [管理员入口功能有限] → 本次只保证首次配置闭环，后续出现真实管理需求再扩展。
- [固定仿真题答案公开] → 仅用于 simulation，并使用稳定标识与醒目标注；real 不复用。
- [初始化覆盖已有数据] → 只在没有可用配置时创建稳定仿真基线，测试重复执行和既有配置保护。

## Migration Plan

1. 增加最小可用性判断并接入申请页与考试开始服务。
2. 增加仿真基线确保函数并接入 simulation reset/初始化。
3. 增加管理员 workspace 最小配置入口。
4. 补充权限、泄露、重置和页面测试并同步直接相关文档。

回滚不得删除已经发布的题目、政策或考试历史。
