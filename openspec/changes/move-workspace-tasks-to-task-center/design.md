## Context

首页当前查询并渲染开放任务与本人活动任务，领取和劳动提交表单也在首页。任务详情已存在但只读且仅本人任务可访问；Workspace Summary 同时返回两组无人消费的任务列表。

## Goals / Non-Goals

**Goals:** 把任务列表与操作迁入任务领域页面，删除首页和 Summary 重复输出。

**Non-Goals:** 不修改任务 service、状态机、积分预算或治理验收页面。

## Decisions

### 1. 使用任务中心作为列表入口

新增固定路由 `tasks/`，在动态任务详情路由之前注册。中心使用三个有界查询，分别显示当前、开放和最近结束任务。

### 2. 详情可见范围为开放任务或本人任务

开放任务必须可被成员发现和领取；非开放任务仅 assignee 本人可见。领取和提交动作仍由 service 做最终校验，不在模板推导权限。

### 3. 操作后返回任务详情

领取成功、提交成功和领域错误均返回原任务详情，使操作反馈留在任务上下文；首页不再承担表单错误展示。

### 4. 删除 Summary 字段而不保留空数组

仓库内无实际消费者，先更新技术契约，再删除 payload 和首页 context 查询。

## Risks / Trade-offs

- [固定任务路由再次被动态详情遮蔽] → `tasks/` 与固定管理路由位于动态路由前，并增加 resolver 回归。
- [开放任务详情泄露不必要数据] → 只展示 Task 既有公开领取信息，劳动与验收 metadata 仅本人任务显示。
- [操作入口迁移造成回归] → 复用原 POST 路由和 service，覆盖领取、提交、错误与权限测试。

## Migration Plan

先更新契约和任务中心/详情，再改操作返回与事务链接，最后删除首页模块和 context 字段。无数据迁移，回滚时整体恢复首页列表与 API 字段。
