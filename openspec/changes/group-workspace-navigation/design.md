## Context

参见 `proposal.md` 的动机。当前 Workspace 顶部导航在单个 `nav` 内平铺全部链接，部分链接使用 `btn-accent`，其余使用默认 `btn`；在当前 daisyUI 主题下形成黑白混排，但颜色并不对应稳定的业务语义。所有入口可见性目前由模板上下文中的职责布尔值控制。

## Goals / Non-Goals

**Goals:**

- 在一个导航区域内提供三个清晰、可访问的具名分组。
- 保持所有现有 URL、链接文字和条件判断不变。
- 让桌面和窄屏布局都能自然换行，不依赖固定宽度。
- 用已有 Tailwind/daisyUI 能力完成，不增加前端依赖。

**Non-Goals:**

- 不把导航配置迁移到 Python 或数据库。
- 不改变 Workspace 服务端上下文、权限计算或业务路由。
- 不建立新的全站导航组件或主题 token。

## Decisions

### 1. 在模板中使用具名容器分组

每组使用带 `aria-labelledby` 的容器，组名作为可见标题，组内链接继续使用现有 Django 模板条件。这样既改善视觉扫描，也让辅助技术能够识别分组。

备选方案是只增加分隔线或继续以按钮颜色区分。该方案不能明确说明类别含义，且仍会把主题颜色误认为优先级，因此不采用。

### 2. 分组映射按入口目的确定

- “个人功能”：任务中心、财务/报销、申请执衡者、积分转账、兑换订单、公开资料。
- “治理职责”：成员报名审核、招募方向、财务职责、待处理提案。
- “运营管理”：创建任务、任务验收、兑换履约、积分预算、商户结算、资源库存、采购管理。

入口只移动位置，不改文字、URL 或原有可见条件。职责分组只有在至少一种对应职责成立时渲染，避免普通成员看到空容器。

备选方案是按现有黑白颜色直接切成两组，但颜色来源于样式类而非业务规则，无法形成可信的信息架构，因此不采用。

### 3. 统一按钮视觉层级

所有组内链接统一使用默认小按钮。分组标题和容器负责表达类别，按钮颜色不再承担分类或优先级语义。

备选方案是为三组分配三种颜色。它会再次把类别绑定到主题色，并增加无必要的视觉噪声，因此不采用。

### 4. 公共页头导航项禁止内部换行

公共页头的链接与提交按钮统一增加 `whitespace-nowrap`，只禁止单个短标签内部换行，不改变导航项顺序、退出的 POST 语义或整个页头的权限逻辑。

备选方案是只给“退出”按钮增加固定宽度。该方案把当前文案硬编码进布局，其他中文短标签在更窄宽度下仍可能出现同类问题，因此不采用。

## Risks / Trade-offs

- [分组容器使黄色页头变高] → 使用响应式多列网格和组内换行，在中等及以上宽度并排展示，窄屏自然堆叠。
- [移动入口位置影响熟悉旧布局的用户] → 保留全部链接文字与目标地址，并通过清晰的固定组名降低重新定位成本。
- [模板条件调整时误改权限] → 保留每个链接原有条件，并增加不同职责成员的回归测试。
- [页头总宽度仍可能超过极窄视口] → 本次只保证标签内部不拆字，不改变全站页头的响应式信息架构；后续如需支持更窄视口，应独立设计折叠菜单。

## Migration Plan

部署时随模板一并发布重新构建的 Tailwind CSS，无数据迁移。若需回滚，可同时恢复模板和编译后的 CSS；服务端数据与权限无需处理。
