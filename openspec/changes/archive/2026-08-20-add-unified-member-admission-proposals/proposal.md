## Why

旧提案系统已经删除，成员报名目前只能保存资料，后续集体决策必须失败关闭。现在需要建立一套新的、可扩展且可审计的统一提案核心，并先用守约者准入恢复一个完整业务闭环，证明未来新增角色或提案类型不需要再次复制投票系统。

## What Changes

### 目标

- 新增统一提案生命周期，覆盖创建、冻结选民规则、开始表决、实名投票、截止与结果判定、授权执行和审计证据。
- 提案创建时引用受制度约束的选民规则模板；参与角色和资格通过稳定目录引用表达，不按角色名称编写提案核心分支。
- 将守约者准入作为第一个业务适配器：贡献者提交报名后创建准入提案，通过后由明确授权的执行者调用既有领域服务授予一年期守约者资格，拒绝时记录实名决定者。
- 页面分别向申请人、合格选民和有权执行者展示真实状态与可用动作；无资格用户获得明确拒绝原因。
- 保持 real 与 simulation world 隔离，并为提案、选民规则、投票、结果、执行及来源报名保存完整审计链。
- 更新公开技术契约、数据库结构、治理边界、成员工作台、Admin 和开发文档。

### 非目标

- 本次不迁移角色任命、角色卸任、财务职责任命、社区共议、守约事务、专业事务、管理事务、公开反馈转行动或仿真自动决策。
- 本次不允许任意用户创建自定义规则表达式，也不提供自由拼装 SQL、代码或前端条件的能力。
- 本次不恢复旧 `Proposal`、旧投票模型、旧 URL、旧服务或兼容门面。
- 本次不为具体个人增加角色、授权例外或硬编码主体。

### 权限影响

- 发起、投票、判定和执行是相互独立的权限边界；能够管理提案不自动获得投票权，管理员不自动成为执衡者。
- 服务层必须执行与页面相同的授权检查，任何内部调用、Admin 或命令均不得绕过。
- OpenFGA 不可用、规则缺失、规则版本不匹配或执行者无权时全部失败关闭。

### 数据影响

- 新增全新的统一提案、规则版本、选民快照、实名投票、决策结果、执行记录及报名来源关联模型。
- 当前项目未上线，不迁移或兼容任何旧提案数据；新结构从干净迁移基线创建。
- 既有 `MemberApplication` 报名资料继续保留，并通过明确来源关系连接新提案；不得复制报名权威状态。

### 公开契约影响

- 新增或修改提案列表、详情、投票和执行所需的 API/schema/payload 契约。
- Docs 必须明确区分当前已开放的成员准入提案与仍然失败关闭的其他提案业务。

## Capabilities

### New Capabilities

- `unified-proposal-lifecycle`: 定义统一提案从创建到授权执行的通用状态机、实名责任、审计、幂等和 world 隔离规则。
- `member-admission-proposal`: 定义守约者报名如何进入统一提案、由合格参与者决定并通过既有角色领域服务执行。

### Modified Capabilities

- `configurable-electorate-rules`: 将既有选民规则制度要求落实到统一提案的规则版本、快照、实时资格复核和目录扩展边界。
- `legacy-proposal-retirement`: 允许已经由新统一提案系统完整承接的成员准入流程退出失败关闭状态，同时继续禁止任何旧实现复活。

## Impact

- 影响 `core.models` 中的治理模型、统一提案领域服务、选民规则评估、授权服务与 OpenFGA 模型。
- 影响 `workspace` 的成员报名列表、详情、投票和执行入口，以及只读审计展示和必要的 Django Admin 配置边界。
- 影响 world 数据库迁移、real/simulation 隔离测试、演示与仿真失败关闭边界。
- 影响 sibling Docs 的技术契约、数据库结构、治理边界、成员工作台、Admin、产品规划和开发指南。
- 不新增第三方依赖，不改变贡献者、守约者、执衡者和管理员的正式角色语义。
