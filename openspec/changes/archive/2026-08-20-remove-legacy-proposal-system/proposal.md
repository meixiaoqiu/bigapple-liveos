## Why

当前仓库同时存在旧 `Proposal` / `ProposalVote` / `ProposalExecution` 体系和新 `ApprovalProposal` / `ApprovalDecision` 体系。旧系统仍在成员准入、角色任命、财务职责、仿真和观察页面中静默承担权威流程，而部分旧页面入口已经被删除，造成“看似已迁移、实际仍运行旧代码”的半迁移状态。项目尚未上线且 world 数据可以重置，现在应先彻底移除旧系统，使所有未迁移依赖在开发检查和测试中明确暴露，再单独完善新统一提案系统。

## What Changes

- **BREAKING** 删除旧 `Proposal`、`ProposalVote`、`ProposalExecution` 及仅为旧体系服务的选民规则模型、领域模块、Admin、命令、信号、事件投影和公开展示。
- **BREAKING** 删除所有业务模型指向旧提案的字段，包括成员报名、角色任命、财务职责、计划修订建议、事件反馈和仿真记录中的旧提案关联。
- **BREAKING** 删除旧提案的页面、URL、API、模板分支、演示数据、仿真驱动逻辑和测试辅助代码；不得保留兼容门面、空壳适配器或回退读取。
- 增加机械检查，禁止产品代码重新导入旧模型、调用旧服务、访问旧字段或使用旧数据库表名。
- 运行全仓依赖审计，把每一个因删除旧系统而失效的业务流程记录为新统一提案系统的待迁移清单。
- 对尚未由新提案系统覆盖的用户入口失败关闭，显示明确的“尚未迁移，暂不可用”，不得返回 500，也不得回退到旧实现。
- 保留成员准入、角色任命、社区共议、专业事务、管理事务等业务制度要求；本变更只删除旧技术实现，不重新设计新提案系统。
- 未上线环境不迁移旧提案数据，不保留旧数据库兼容结构；通过重置 real/simulation 开发数据库使用新结构。

### 目标

- 仓库中不存在可运行的旧提案系统。
- 任一未迁移业务都能在检查、测试或明确的关闭页面中暴露，而不是静默使用旧代码。
- 形成完整、可追踪的新提案系统迁移缺口清单。

### 非目标

- 本变更不扩展 `ApprovalProposal` 的投票、选民规则、阈值或执行能力。
- 本变更不恢复旧提案页面、URL 或兼容适配层。
- 本变更不承诺让所有原有提案业务立即恢复可用。
- 本变更不迁移或保留现有 world 中的旧提案、投票和执行数据。

### 权限影响

- 依赖旧 `Proposal` 计算选民、投票或执行资格的权限路径将停止工作并失败关闭。
- 删除旧系统不得扩大管理员、执衡者、守约者或 Django staff/superuser 的权限。
- 新系统尚未承接的流程不得通过角色名称、Django 标记或直接数据库写入绕过。

### 数据影响

- 删除旧提案及其关联表、字段和开发数据，属于破坏性 schema 变更。
- 当前未上线，不提供旧数据迁移、双写、读取兼容或回滚到旧系统的运行时路径。
- OpenSpec 过程文档和 Git 历史保留旧制度实现的历史信息。

### 公开契约影响

- 所有暴露旧提案、投票、执行或选民快照的 API/schema/payload 必须删除或明确标记为暂不可用。
- 修改公开 contract 前必须同步 sibling Docs 仓库中的技术契约、API、数据库结构和治理边界文档。

## Capabilities

### New Capabilities

- `legacy-proposal-retirement`: 定义旧提案系统必须被完整删除、残余依赖必须被机械阻止、未迁移用户流程必须失败关闭的要求。

### Modified Capabilities

- 无。`configurable-electorate-rules` 继续作为新统一提案系统必须重新实现的制度规格，本次删除旧实现不降低或改写该长期要求。

## Impact

- 主要影响 `core.models.proposals`、`core.proposals`、`core.electorate_rules`、相关领域服务、`workspace`、`observer`、`simulation`、`simulation_lab`、Django Admin、管理命令和测试。
- 影响 `MemberApplication`、角色任命、财务职责任命、计划修订、反馈与仿真等引用旧提案的模型和流程。
- 影响数据库 migrations、OpenFGA 投影、事件 payload、演示/仿真 seed、API 和技术契约。
- 不新增第三方依赖。
