## Context

参见 `proposal.md`。当前模板一次渲染三个 `matter_group.html`，每组都有大型容器、标题、数量和完整事务卡片；这保证了无 JavaScript 的可用性，但在 480px 竖版画布中产生较长的空状态和重复视觉边框。服务器端 `work_items.matters` 已经完成分组、排序和权限相关投影，本轮不得触碰该读模型。

## Goals / Non-Goals

**Goals:**

- 在不新增服务器端参数或查询的情况下，实现可访问的客户端标签页增强。
- 保持服务端 HTML 中三个分组和所有事务事实完整存在。
- 缩短空状态和事务卡片的视觉高度，同时不隐藏现有字段。

**Non-Goals:**

- 不引入前端框架、外部脚本、浏览器存储或 URL 查询状态。
- 不懒加载事务分组，也不改变服务器端投影构建次数。
- 不把“等待他人”合并进其他分组，不重新解释 `action_label` 或责任字段。

## Decisions

### 1. 使用页面内渐进增强标签页

模板继续按“需要我处理”“等待他人”“最近结束”顺序渲染全部面板。标签控制条初始带 `hidden`，面板初始不带 `hidden`；页面内的小型脚本初始化成功后再显示标签控制条、激活第一项并隐藏另外两个面板。

这样脚本不可用时三个分组自然退化为连续内容，不会因硬编码 `hidden` 丢失事务。未采用服务器端 `?matter_group=` 切换，因为它会增加 view 参数和整页请求，却不能改善当前已经构建全部投影的查询成本；未采用默认隐藏面板，因为这会破坏无脚本可用性。

### 2. 实现标准标签语义和键盘行为

控制条使用 `role="tablist"`，每个按钮使用 `role="tab"`、稳定 ID、`aria-controls`、`aria-selected` 和 roving `tabindex`；面板使用 `role="tabpanel"`、稳定 ID 和 `aria-labelledby`。初始化函数统一更新这些状态，并处理点击、ArrowLeft、ArrowRight、Home 和 End。

未只使用普通按钮加 click 事件，因为那无法向辅助技术表达标签与内容面板关系，也缺少符合预期的键盘操作。

### 3. 保留三组并默认“需要我处理”

参考稿只画出“需要我处理”和“最近结束”，但当前产品还存在语义独立的“等待他人”。本轮把三组都放进标签栏，顺序沿用投影顺序，默认第一组，避免视觉参考造成业务信息删除。

不记忆上次选择。浏览器存储会引入跨会话状态和测试分支，对当前单页渐进改造没有必要。

### 4. partial 继续负责单组及事务卡片

`matter_group.html` 继续循环现有 `items`，但外层改为标签面板并接收稳定的面板/标签标识及详情按钮文案。无脚本时可见的组标题带专用 data 属性；增强成功后脚本隐藏重复组标题，由标签承担分组名称。

事务卡片移除 daisyUI 重型 `card` 嵌套和多层 badge 视觉，但保留所有现有字段。行动分组的链接可显示“进入处理”，等待和结束分组使用中性的“查看详情”；两者均使用原 `target_url`，不增加动作能力。

### 5. 测试锁定事实而非仅锁定样式

Django 测试验证三个标签的顺序、数量、ARIA 关联、面板初始无 `hidden`、事务字段与 URL 保留、空状态和后续模块顺序。对脚本源代码只验证初始化标记和支持的按键集合；实际选中切换与焦点行为应通过本地浏览器人工检查。

### 6. 为首页引入 bigapple 主题以对齐设计稿配色

参考设计稿采用黑白灰配色（黑色主色、白色背景、浅灰描边），而 Workspace 当前沿用 `bumblebee`（黄色主色）。若继续用 `bumblebee`，选中标签下划线等主色元素会显示为黄色，与设计稿不符；若逐模块硬编码颜色，则会产生大量分散的自定义样式。

因此本轮在 `theme/static_src/src/styles.css` 定义接近设计稿的 `bigapple` 主题（`--color-primary` 为纯黑、`--color-base-100` 为白、`--color-base-300` 为浅灰描边），并把 Workspace 首页的 `data-theme` 切换为该主题。这样 `text-primary`、`border-primary` 等工具类自动呈现黑色，无需为标签页或按钮单独写颜色。

`bigapple` 仅用于 Workspace 首页；其他 Workspace 页面仍使用 `bumblebee`，全站统一换肤属于另一个变更，不在本轮范围。

## Risks / Trade-offs

- [初始化前短暂显示三个分组] → 脚本放在页面末尾并立即初始化，闪动时间最小；优先保证无脚本内容完整。
- [内联脚本随模板增长] → 本轮逻辑仅服务单页且规模很小；若后续第二个页面复用标签页，再抽取本地静态模块。
- [隐藏面板中的链接仍留在 DOM] → 使用原生 `hidden`，隐藏内容不参与布局和常规键盘导航；切换时同步移除当前面板的 `hidden`。
- [紧凑布局可能让长责任文本换行] → 允许自然换行，不截断权威事实，不设置固定卡片高度。
- [标签数量只反映当前最多展示的投影列表] → 继续使用现有列表长度；本轮不改变投影限制，也不将其误称为领域全量统计。

## Migration Plan

1. 改造事务区段和 partial，同时保持所有模板变量及三个 include 来源不变。
2. 加入渐进增强脚本、ARIA 和键盘行为。
3. 更新测试、成员 Workspace 文档并重建 Tailwind CSS。
4. 在有事务、全空状态、窄屏和宽屏场景检查标签切换与无横向溢出。
5. 若需回滚，恢复原事务区段和 partial；无数据、API 或权限迁移。
