## Why

当前有效守约者虽然已有执衡者自助申请服务，但没有成员入口，也没有申请前的知识考核，导致仿真世界在缺少执衡者时无法审核新的守约者申请，继而阻塞财务职责补充和报销审核。现在需要建立可从一题起步、由管理员持续维护的题库与考试闭环，使执衡者资格既可获得又有明确门槛和审计依据。

## What Changes

- 在成员工作台增加执衡者资格说明、考试入口、考试结果和当前任期展示；只有当前有效守约者可以参加。
- 新增执衡者题库、题目选项和题库版本/启用状态，由具备独立题库维护权限的管理员在 control plane Admin 中维护；普通成员和 Django 技术账号标记不能绕过业务权限。
- 每次考试从当前已发布题库中随机抽取配置数量的题目；题库只有一题时抽取该题，不因题量少而阻塞第一版上线。
- 服务端保存考试尝试、抽题快照、答案、得分、及格线、结果和时间，客户端不得提交正确答案或自行决定分数。
- 达到及格线后，在同一领域事务中创建一年期执衡者任命并记录来源；未通过、题库不可用、重复提交或并发提交均不得产生执衡者任期。
- 修改现有“守约者申请执衡者即可立即任命”的规则：仍无需人工审核，但必须先通过当前考试；任期到期后再次申请也必须重新考试。
- 更新仿真基线和回归流程，证明从已有守约者参加考试成为执衡者、审核新成员准入，到后续财务职责准备的前置链路可重复执行。
- 非目标：远程监考、防作弊摄像、主观题人工阅卷、开放题库导入导出、跨 world 共享考试记录、自动授予财务角色或自动审核报销。
- 权限影响：新增明确的执衡者题库维护权限并绑定管理员；考试资格仍要求有效守约者，考试通过只授予执衡者任期，不授予管理员或任何 `finance.*` 权限。
- 数据影响：新增题库题目、选项/答案、发布状态及考试尝试和答题快照等 world 权威记录；记录只追加或显式停用，既有执衡者任期不追溯撤销。
- 公开契约影响：第一版只新增 Django workspace 与 Admin 能力，不新增或修改公共 API、schema 或 payload，因此技术契约无需变化。

## Capabilities

### New Capabilities

- `deliberator-qualification-exam`: 覆盖管理员维护执衡者题库、随机组卷、服务端评分、考试审计和通过后原子授予一年执衡者任期。

### Modified Capabilities

- `role-authority-facts`: 将执衡者自助申请从无条件即时任命修改为“有效守约者通过资格考试后即时任命”，并保持一年任期、职责独立和持续授权校验。

## Impact

- Live OS：`core.models` 中的执衡者考试领域模型、迁移、题库与考试领域服务、`core.deliberation_services`、角色权限基线、Admin、workspace 页面/路由、事件账本和测试。
- 仿真：角色基线与端到端验收需要通过正式考试服务创建执衡者，不再直接调用无考核任命路径。
- 文档：更新 sibling `bigapple-docs` 中数据库结构、角色权威事实、成员工作台、Admin、仿真和开发说明。
- 依赖：复用 Django ORM、事务、表单和现有随机库，不引入第三方考试平台或新依赖。
