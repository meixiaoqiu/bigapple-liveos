## Context

参见 [proposal.md](proposal.md) 的动机。当前 `apply_for_deliberator_term()` 会在有效守约者调用后直接创建一年任期，但没有 workspace 路由；角色基线和测试会直接调用该服务。成员准入提案的选民必须同时具有有效守约者资格和执衡者任期，因此一个没有执衡者的仿真 world 会陷入无法审核新守约者的制度死锁。

本次在现有 Django 权威模型、world 数据库路由、RoleAssignment、OpenFGA 和统一事件账本内增加考试能力。技术契约中没有执衡者申请公共 API；第一版继续使用 Django workspace 和 control plane Admin。

## Goals / Non-Goals

**Goals:**

- 将执衡者任期的唯一自助取得路径改为服务端考试通过，不保留可绕过考试的公共服务入口。
- 允许题库从一道题起步，并在增加题目后无需修改数据模型即可随机组卷。
- 保存足以证明“谁在何时按哪套题目和标准取得任期”的权威事实。
- 让典守者通过独立权限维护题库，同时保持 Django 技术管理员和业务授权分离。
- 保持考试、任命、OpenFGA 投影和 world 数据严格隔离。

**Non-Goals:**

- 不实现主观题、人工阅卷、监考、摄像、防截屏或第三方考试平台。
- 不把执衡者考试复用为通用培训/LMS 或专业资格考试框架。
- 不因考试通过自动授予财务、典守或专业资格。
- 不改变守约者准入提案的多数决和选民规则。

## Decisions

### 1. 使用窄领域模型而不是通用考试平台

新增 `DeliberatorExamPolicy`、`DeliberatorExamQuestion` 和 `DeliberatorExamAttempt`。Policy 保存版本、抽题数、及格百分比、状态和发布责任；Question 保存稳定题目标识、版本、题干、选项、正确选项、分值、解释和状态；Attempt 保存成员、政策版本、题目快照、作答、得分、结果、开始/提交时间及产生的 RoleAssignment。

第一版把单选题选项保存在受校验的 JSON 中，而不是拆成通用 Question/Choice/Exam/Course 多层模型。原因是当前只有执衡者单选考试，JSON 快照能完整保留历史且减少无真实需求的抽象。字段服务会验证选项 ID 唯一、至少两个选项、正确选项存在、分值为正。

替代方案是建立通用考试平台，但会提前引入课程、题型、试卷和多领域权限，明显超出当前目标。

### 2. 已发布政策和题目采用版本化替换

草稿可以编辑；一旦发布并可能被抽取，其评分内容不再原地修改。典守者修改时创建同一稳定题目标识的新版本，旧版本停用但保留。每个 world 同时至多有一项当前生效政策；发布新政策时显式结束旧政策。

单一生效政策使用可在 MySQL 执行的唯一槽位约束：仅 `active` 记录保存固定槽位值 `1`，其他状态必须为空。发布服务在事务中结束旧政策并创建新政策；并发唯一冲突转换为领域错误并回滚整次发布。

即使题目版本保留，Attempt 仍保存题干、选项、正确选项、分值、抽题顺序、及格线和政策版本的私有快照。这样归档和审计不依赖后续题库状态，也不会因误操作改写既有成绩。

替代方案是允许直接编辑已发布题目并只引用外键，但会让历史考试的事实随题库变化，不符合权威审计边界。

### 3. 使用服务端安全随机抽样并创建持久化尝试

开始考试时，在可信 world 数据库内锁定当前政策，读取满足状态和生效时间的题目版本，使用 `secrets.SystemRandom().sample()` 无重复抽取。抽题和 Attempt 快照创建在一个数据库事务中完成。题量不足时在创建 Attempt 前失败关闭。

尝试使用不可预测稳定 ID，并绑定当前成员。workspace 只输出快照中的题干与选项，不输出正确选项、解释或评分内部字段。提交只接受 `attempt_id` 与 `{question_snapshot_id: selected_option_id}`，未知、重复或缺失答案按明确表单错误处理。

不使用数据库 `ORDER BY RAND()`，因为它的性能和可测试性较差；不让浏览器抽题，因为客户端可以控制题目集合。

### 4. 评分与任期创建由一个领域事务完成

新增考试服务负责：重新验证当前守约者资格和账号状态、锁定 Attempt、验证未完成状态、按私有快照评分、写入最终结果；通过时调用只接受已锁定通过 Attempt 的内部任命函数创建一年 RoleAssignment，并把 Attempt 与任命互相关联。公开的 `apply_for_deliberator_term()` 不再提供无考试参数的绕过路径；角色基线和仿真数据改用显式的受控基线辅助函数或创建并通过固定测试考试。

数据库唯一约束配合 `select_for_update` 防止同一 Attempt 重复完成和同一成员并发产生重叠 active 任期。考试结果、RoleAssignment 和统一 `role_assigned` 事件处于同一事务；任何异常全部回滚。

未通过后允许立即创建新的独立 Attempt。第一版不设置冷却期或次数限制，因为现阶段仅有一题，硬编码限制不能提供真实防作弊价值；所有失败尝试保留，未来有足够题量和运营证据后再增加可配置频控。

### 5. 题库维护使用独立治理权限

新增 `governance.manage_deliberator_exam`，绑定规范典守者角色。Admin 的题库和政策入口必须通过 `AuthorizationService` 校验绑定成员的业务权限；`is_staff`/`is_superuser` 只允许进入技术后台，不替代 world 业务授权。考试尝试只读，禁止后台改分或手工改为通过。

题库变化写统一事件账本，payload 只保存题目标识、版本、状态和责任人，不保存正确答案或完整题目内容。正确答案只存在于 world 私有数据库和 Attempt 私有评分快照，不进入公开 Event、日志或页面。

### 6. Workspace 提供完整自助入口

在成员工作台增加执衡者卡片：非守约者显示前置条件；有效守约者可开始考试；已有任期显示起止时间；题库不可用显示明确维护提示。考试 GET 只读取当前成员自己的 Attempt，POST 由表单验证选项后调用服务。通过后跳转结果页并显示新任期；失败显示得分与是否及格，不显示正确答案。

页面不允许通过 URL 选择 Member。所有身份从登录 User 绑定的 Member 推导，并复用当前 fixed-world 路由。

### 7. 仿真启动需要可恢复的首位执衡者路径

系统初始化已有首位典守者同时具备守约者资格。部署迁移后为每个 world 建立默认考试政策和第一道可替换示例题；初始化典守者可以通过与普通成员相同的 workspace 考试成为首位执衡者，从而打破成员准入死锁。示例题不得包含真实秘密或个人信息，典守者可以在投入正式使用前替换版本。

自动化测试和仿真 smoke 必须走开始考试、提交答案、取得执衡者任期的真实服务路径。生产/开发数据库不为测试自动写入通过记录。

## Risks / Trade-offs

- [只有一道题时容易记住答案] → 第一版承认题量限制但建立可扩展题库；不公开正确答案，后续由典守者持续补题。
- [典守者可通过改题操纵门槛] → 独立权限、版本记录、发布责任人和统一事件审计；既有 Attempt 使用不可变快照。
- [随机考试难以稳定测试] → 生产使用安全随机源，服务允许测试注入抽样器或在单题题库下获得确定结果。
- [并发通过产生重复任期] → 锁定成员相关尝试、事务内重新检查 active 任期并使用数据库约束/冲突处理保证最多一届当前任期。
- [正确答案从 Admin、日志或序列化泄漏] → Admin 表单写入但列表和只读页隐藏正确答案；日志、公开 Event 和普通成员结果只输出元数据与分数。
- [题库错误导致无可用考试] → 发布政策前验证题量，workspace 显示题库维护提示；既有执衡者任期不受影响。

## Migration Plan

1. 新增考试政策、题目和尝试模型、约束与权限迁移，不改写既有 RoleAssignment。
2. 初始化一项抽取一题的默认政策和一道可替换示例题；既有有效执衡者继续履职，到期后按新考试规则续任。
3. 部署题库 Admin 与 workspace 入口，将原直接申请服务收紧为仅由通过考试事务调用。
4. 更新角色基线、仿真 seed 和 smoke，先让初始化典守者通过考试成为首位执衡者，再验证其审核新守约者申请。
5. 更新 OpenFGA tuple 后运行成员准入、角色、考试、workspace、Admin、world 隔离和完整回归。

回滚代码时保留考试表和已有任期，不执行破坏性逆迁移；旧代码不得重新开放无考试的执衡者直接申请入口。如考试入口必须临时关闭，既有执衡者继续按原期限履职，新任期暂停产生直至修复。
